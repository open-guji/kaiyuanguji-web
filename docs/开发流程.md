# 开发流程（分支、本地测试、发测试站）

A41 I 线，2026-11-06。适用 kaiyuanguji-web 与 book-index-manager 两个仓；做法仿 open-guji-cv。

## 1. 分支

```
feat/…、claude/… ──PR──▶ dev ──（准备发版，切出）──▶ rc/vX.Y.Z ──（测完，merge commit）──▶ main
```

- **所有 PR 投 dev。** 合进 dev 不触发任何部署（deploy.yml 只在 push main 时跑），可以随时合、随时攒，没有「每个 PR 两次构建」的额度顾虑。
- **随时发测试站看效果**：Actions → Deploy to EdgeOne → Run workflow，「Use workflow from」选任意分支（dev、rc/…、feat/…），`target=staging`。
- **发版**：从 dev 切 `rc/vX.Y.Z`，测试站验过，再用 **merge commit（不要 squash）** 并进 main。main 之后的上线照旧：push main 发测试站，正式站由 Deploy 手动晋升（AUTO_PROMOTE_CODE=false 不变）。
- rc 上只收本版修复，修完同一改动合回 dev。
- PR 检查（单测、tsc、fulltext 闸门、middleware 全栈）对 `main` 与 `dev` 两个目标都跑。
- 默认分支保持 main（每日数据发布、监控等定时任务按默认分支跑）。
- 红线不变：不碰生产；晋升正式站交 Deploy；AUTO_PROMOTE_CODE、仓库变量、分支保护不改。合并前 `tsc` 必须通过（CI 的 Typecheck 步骤就是它）。

## 2. 依赖 book-index-ui

| 分支 | 依赖写法 | 来源 |
|---|---|---|
| dev | 固定预发布版本，如 `"book-index-ui": "0.66.0-rc.2"` | npm dist-tag `next` |
| main | `^0.66.0` 区间 | npm `latest` |

- 包的预发布：在 book-index-manager 的 dev 上把 `ui/package.json` 的 version 写成 `0.66.0-rc.N`，Actions → Publish book-index-ui → 从 dev 运行。版本带 `-` 时 tag 自动是 `next`，**不会动 latest**；发 latest 时若版本带 `-` 会直接报错。
- **每日自动升依赖**：`bump-bim-ui.yml` 每天 01:30 UTC 查 npm（`next` 与 `latest` 取较高者），比 dev 当前依赖新就开一个升依赖 PR 投 dev，也可手动触发。
- 全部功能完成后：包发正式 `0.66.0`（minor），dev 改依赖 `^0.66.0`，随 rc 并入 main。

## 3. 本地看最新（不发测试站）

一条命令看到「网站 dev ＋ UI 包 dev 源码 ＋ 最新数据」：

```bash
bash nextjs/scripts/local-latest.sh     # 缺什么拉什么，然后起服务，http://localhost:3000
# 或已经准备好了：
cd nextjs && npm run dev:latest
```

`local-latest.sh` 会：把 book-index-manager 浅克隆到网站仓**同级目录**（已有则更新；默认 dev 分支，没有则 main；`BIM_BRANCH=feat/xxx` 换分支）、装网站依赖、再启动 `dev:latest`。云端会话也能跑（能访问 data.openguji.com）。

`dev:latest` 的行为：

- **UI**：`BIM_UI_SRC`（默认 `../../book-index-manager/ui`）经 webpack alias 直连 UI 源码，改 UI 立即热更新，不用 build、不用拷贝、不用 npm link。`BIM_UI_SRC=npm` 则用 node_modules 里装的那版。
  - **不要在 ui/ 目录里装依赖**：UI 源码的 react 等必须解析到网站的 node_modules，否则出现两份 React（报 `useContext of null`）。脚本发现 `ui/node_modules/react` 会直接拒绝启动。
- **数据**：`NEXT_PUBLIC_DATA_SOURCE=cos`，读 `https://data.openguji.com`（现行指针 `latest.json`），不需要本地数据仓。`NEXT_PUBLIC_COS_BASE` 可换。
- **渲染**：默认 `KYG_RENDER_MODE=fullstack`（与测试站一致，`/item/[id]`、`/read/[id]` 才有）。设成空字符串则是静态导出那种，只能看预生成的页面。
- **搜索**：不配 Meilisearch，走浏览器端 L2。

## 4. 常见问题

- 端口被占：`PORT=3100 npm run dev:latest`。
- 页面 404：多半是没开 fullstack（见上），或 id 不存在。
- 样式像旧版：删 `nextjs/.next` 重启。
- 想用别人的 UI 分支：`BIM_BRANCH=<分支> bash nextjs/scripts/local-latest.sh`，或自己在 book-index-manager 里 `git checkout`。
