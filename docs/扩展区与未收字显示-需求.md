# 扩展区生僻字与未收字怎么显示：需求起点（2026-10-20）

> 起因：用户 10-20 在看 vol04 精校页的「相似字」时提出：
> - 有些字网站显示不出来，变成方框；
> - 这不只是审阅页的事，网站上很多扩展区字、Unicode 未收字都有同样的问题。
>
> 用户要新开会话专门研究。本文只写需求、现状和量出来的数，**不定方案**。
> 临时做法（用户 10-20 定）：显示不出来的字一律改显示码位 `U+XXXXX`，见 §2.3。
> 数字来自本会话 10-20 实测，量法写在各节。

---

## 0. 一页话

1. **现状**：
   - 网站字体栈的末尾用花园明朝（HanaMin 0.0.5，jsDelivr／unpkg）兜底扩 A、扩 B–F、兼容区。
   - 花园明朝是 2017 年的字库：扩 A 只到 U+4DB5，扩 B–F 各区缺 Unicode 13 以后补的尾巴，**扩 G、H、I、J 完全没有**。Unicode 18 共 101,997 个统一汉字。
2. **影响不小**：
   - vol04 待审单的相似字去重 3,725 个，网站显示不出来的有 262 个（7.0%）。
   - 缺省展开的前 10 个里有 98 个，**落在 280 张卡中的 92 张上（33%）**。
   - 阅读页、元数据页上的扩展区字同理，还没量（§5 待做）。
3. **未收字**（Unicode 没有码位的字形）另是一类：
   - 书里用组字式（`[口*恒]`、`{宀兒}`）或 IDS 串（`⿰亻⿱氏丁`）记；
   - cv 的关系库里有 37,826 个未编码形（多来自字统网派生、cjkvi），将来也会出现在网站上。
   - 网站现在把它们当普通文本显示。
4. **能覆盖的免费字体**：只有 Jigmo（CC0）把 vol04 的 3,725 个相似字全覆盖。但 Jigmo 的扩 J 是 0 字；扩 J 和更新的区要另找字体或别的办法。
5. 需要定的是一套**全站统一的显示方案**：
   - 字体怎么分发、按需加载；
   - 显示不出来怎么兜底；
   - 未收字怎么画；
   - 审阅页的「字形图」是否还需要。

## 1. 要显示的字有哪几类

| 类 | 例子 | 出处 | 现在怎么显示 |
|---|---|---|---|
| 基本区 | 之 | 全站 | 系统字体 |
| 扩 A–F（花园明朝有的部分） | 㐀 𠀀 | 阅读页、精校页 | 花园明朝 |
| 扩 A 尾巴 U+4DB6–4DBF、扩 B–F 各区新补的尾巴 | U+2A6D7 | 同上 | **方框** |
| 扩 G（U+30000–3134F）、扩 H（U+31350–323AF）、扩 I（U+2EBF0–2EE5F）、扩 J（U+323B0–3347F） | U+30EDD | 相似字、整理本、关系库 | **方框** |
| 兼容区 | 豈 | 少量 | 花园明朝；cv 导出时已折成统一汉字 |
| 私用区（PUA） | U+E000 起 | 外来转录（全字庫、教育部、全宋體三套 PUA 互不相通） | 方框或乱字 |
| 组字式 | `[口*恒]` `{宀兒}` `[B18D]` | book-text 转录本（CBETA、维基）；**不得批量换掉**（book-text 规矩） | 原样文本 |
| IDS 串（未收字） | `⿰亻⿱氏丁` | cv 关系库的未编码形；以后的「以字找字」可能给出 | 原样文本 |
| 异体选择符（IVS） | 字＋U+E0100 | Unihan／IVD；cv 一律去掉 | 不出现 |

## 2. 现状

### 2.1 网站（本仓）
- `nextjs/src/app/globals.css` 开头摘了 `hanamin@0.0.5` 的 `@font-face`，按 `unicode-range` 分块，src 先 jsDelivr 再 unpkg。字体栈末尾是 `"HanaMinA", "HanaMinB"`（overview#421）。
- 实际声明的区段（10-20 从 css 抽出）：
  - HanaMinA：U+3400–4DB5、U+F900–FA6D、U+FA70–FAD9、U+2F800–2FA1D；
  - HanaMinB：U+20000–2A6D6、U+2A700–2B734、U+2B740–2B81D、U+2B820–2CEA1、U+2CEB0–2EBE0。
- 精校页（`app/proofing/…/ProofingClient.tsx`）：
  - 相似字 `alt` 的每个字可以带一张字形图 `g`（雪碧图，由 ai-team `GUJI-557/alt_build.py` 生成），没图就显示文字；
  - 10-20 起，显示不出来的字显示码位（§2.3）。
- **对读章生僻字子集（GUJI-701，10-20 已上线，见 `docs/reader-performance.md` P1-3）**：
  - 打包时按章抽出生僻字，从花园明朝分片合成一个 `<章>.font.woff2`（样本章 35 字、11KB），托管在本站 COS；
  - 服务端渲染时追加同字族的 `@font-face`。按 CSS 规则，后定义的先查，所以大分片不再被请求。
  - 它只解决「花园明朝有的字」的加载量：
    - 收字限于花园明朝 `unicode-range` 内、分片里确有字形的码位，**扩 G 以后照样没有**；
    - 只管对读章的首屏，**精校页不在内**。
  - 这条管线（按页抽字 → 合成子集 woff2 → 托管 COS → 追加 `@font-face`）可以直接复用：把字源从花园明朝扩到 Jigmo，就能覆盖扩 G–I；同样的做法也能给每份待审单出一个子集字体，替代审阅页的雪碧图。
- **国内访问**：网站在国内备案、主要读者在国内。花园明朝的分片走 jsDelivr／unpkg，这两个在国内的可达性和速度没有量过，是个隐患（GUJI-701 的子集已托管 COS，但只覆盖对读章首屏）。
  - 10-20 在云会话的测试浏览器里，jsDelivr 的分片一直卡在「加载中」，扩 B 的字照样显示成方框。
  - 这时 §2.3 的判据仍会认为「能显示」，不会改成码位。判据只看字体声明，不看字体有没有真的加载下来。

### 2.2 别处的做法（可参考）
- **cv 控制台**：字形图由后端用 cv 仓 `fonts/` 现渲染（`/api/glyphlib/font/{字}.png?font=…`），先 I.Ming，再 Jigmo；浏览器端不依赖字体。
- **审阅页字形雪碧图**（`alt_build.py`）：
  - 每个字用 cv 字体渲染成 256×256 灰度图（I.Ming 优先，其次 Jigmo），去白边，等比缩进 96×96 格的八成大小，拼成每行 21 格的 WebP（质量 80）；
  - 发布走 open-guji-dataset 的 GitHub Release＋book-text 指针，由 `sync-proof-sprites` 传 COS；
  - vol04 实测：3,725 字、两张图共 4.2 MB，整册塞一张，太重，没有发。
  - **用户 10-20 定**：open-guji-dataset 只放测试集，不放字形图；字形图放哪、还要不要雪碧图，等本文的字体方案定了再说。在那之前精校页只显示字，显示不出来的显示码位（§2.3）。

### 2.3 临时兜底（10-20 已做）
- `nextjs/src/lib/zi-display.ts`：
  - `SHOWABLE_RANGES` 是本站字体能显示的区段，即花园明朝的 `unicode-range` 加上基本区；
  - `canShow(c)` 判断能否显示，`shownZi(c)` 不能显示时返回 `U+XXXXX`。
  - 单测会和 globals.css 的字体区段对账：加了字体、忘了改表就红。
- 精校页上显示字的地方（候选、相似字、机器读字、大字、整理本对位字、上下文、依据说明、「已提交」）都过这一层。
  - 码位用等宽小字显示，悬停显示原字；
  - 提交、复制、无障碍标签仍是原字。
- 这只是兜底：码位对读者没有意义，只是比方框诚实。

## 4. 需求

### 4.1 必须
1. **不出方框**：每个已编码汉字，要么显示字形，要么显示可读的兜底（现在是码位），永远不显示方框或乱码。
2. **不改文本**：显示层的替换不能改底层文本。复制、选中、搜索、提交拿到的都是原字；码位、图片只是外观。
3. **全站一套**：阅读页、精校页、元数据、搜索结果、专名页用同一个判据和同一个兜底，不各写各的。
4. **能判断「显示得出来吗」**：浏览器没有可靠的 API。现在的做法是按字体声明的区段判断（§2.3）；换方案时这个判据要跟着字体一起出，比如构建时从字体 cmap 生成覆盖表。
5. **加载要轻**：
   - 首屏不因生僻字多下载字体；
   - 按页面上实际出现的字按需加载；
   - 单块建议不超过约 150 KB。
   - 要在国内网络下实测（读者主要在国内），字体最好托管在本站 COS／CDN，不依赖海外 CDN。
6. **授权干净**：只用 CC0、OFL、IPA 这类可再分发的字体，逐个记授权。天珩全字库禁用（字形拼凑自商业字体）。TypeLand 康熙字典体是商业字体，不进网站。

### 4.2 应该
7. **风格一致**：古籍正文是明体（宋体）。扩展区兜底最好也是明体系；Jigmo 是明体，遍黑体之类黑体会和正文跳风格。
8. **扩 J 与以后的新区**：Jigmo 没有扩 J。要找能覆盖扩 J 的开源字体并实测覆盖，候选如遍黑体（Plangothic，OFL）、BabelStone Han，都没测过；或者给新区出图。
9. **未收字**（组字式、IDS 串）：
   - 定一种显示：
     - 原样文本；
     - 按 IDS 用 GlyphWiki／KAGE 画成 SVG（GlyphWiki 可自由使用，kage-engine MIT，单字约 14 ms）；
     - 或预先出图。
   - 都要能看出「这是一个字」而不是几个部件。
   - book-text 的组字式要原样保留（book-text 规矩），只改显示。
10. **私用区**：外来转录里的 PUA 字要能识别出处（哪套 PUA），能映射的映射成正字或 IDS，不能的显示码位并标出处。
11. **审阅页**：精校页的相似字现在要靠字形图或字体才能比对字形。字体方案上线后，评估雪碧图还要不要（雪碧图的好处是全站同一个字形，不随读者电脑变）。

### 4.3 可以
12. 渲染风格可选（明体／楷体），给专业读者对照字书用。
13. 服务端出单字 SVG／PNG 的接口（类似 cv 控制台的 `/api/glyphlib/font`），给分享卡片、导出 PDF 用。

## 5. 新会话要先量的
- **book-text 全仓**：各区汉字、PUA、组字式、IDS 串各出现多少（字种数、字次），按书分。这决定扩 G 以后的字在阅读页上多不多。
- **花园明朝在国内的加载**：jsDelivr／unpkg 的可达率与耗时；换成本站 COS 后的对比。
- **候选字体实测覆盖**：遍黑体、BabelStone Han、思源宋体新版、Noto Serif CJK 各区覆盖与授权，重点看扩 G–J。
- **按需加载的实际下载量**：拿 vol04 精校页、几本扩展区字多的阅读页，量一页要拉多少字体块。
- **判据的准确性**：按区段判断「能显示」会高估，因为区段内个别码位字体可能缺。要不要改成逐字覆盖表（构建时从字体 cmap 生成，几十 KB 的位图）。
