# 提交带会员身份：反馈、字判断、讨论由服务端验登录后记会员 ID

2026-11-26 sheldon 提出。状态：**方案，待用户确认后实现。**

## 目标

读者登录后，在网站上提交**反馈、精校页字判断（cellreview）、改字／专名／一段意见（charfix）、讨论（thread）**时，记录是「哪位会员」提交的。身份必须由**服务端从 session cookie 验出来**，前端不能自己填 ID。未登录的读者仍可匿名提交，行为不变。

## 现状（读代码得到）

- 登录态：`session` cookie（HS256 JWT，`sub`＝邮箱，带 `tv`＝tokenVersion），边缘函数里已有 `checkMemberCookie(request, context, allowedRoles)`（`feedback.js`），验签、查成员记录、核对 tokenVersion。目前只用于**管理读**，提交接口都不看登录。
- 匿名身份：提交的 `voter = sha256(aid|ip)` 前 16 位，`aid` 是浏览器 localStorage 里的随机 id；记录只存 voter，不存 aid、不存 IP。反馈（feedback）的限速按 IP。
- 记录是公开可读的一部分（如 `/api/fixes`、每日清单），所以**不能把邮箱写进记录**。

## 方案

### 1. 会员 ID（uid）
- 在成员记录里加一个稳定、不透明的 `uid`（如 `m_` + 12 位随机十六进制），创建成员时生成，**老成员在下一次登录或 `/api/auth/me` 时补发**（记录里没有就生成并写回）。
- uid 不由邮箱推出（邮箱可能换），一旦发出永不变，**可以出现在记录和公开数据里**；邮箱继续只在成员记录里。

### 2. 服务端取身份
- 在 `feedback.js` 新增 `memberFromRequest(request, context)`：复用 `checkMemberCookie` 的验证（验签、成员未被移除、tokenVersion 对得上、**不限角色**），返回 `{ uid, role }` 或 `null`。验不过一律当匿名，**不报错**，不影响匿名提交。
- 提交接口里**忽略前端传来的任何 member／uid 字段**，只认 `memberFromRequest` 的结果。

### 3. 各接口怎么记
| 接口 | 现在 | 登录后 |
|---|---|---|
| cellreview（精校票） | voter＝sha256(aid\|ip)，同格同 voter 覆盖旧票 | voter 改成 `m:<uid>`：**同一会员跨设备、换 IP 仍是同一票**，更新覆盖；值里加 `member: uid` |
| charfix（改字／专名／一段） | 同上 | 同上；key 末段用 `m:<uid>` |
| thread（讨论） | 同上 | 同上，回复带 `member` |
| feedback（反馈） | 匿名，按 IP 限速 | 记录加 `member: uid`；限速改按会员（更宽松）；`contact` 字段可由会员邮箱预填（只给站方看，不公开） |

- 匿名提交保持原样；登录前后提交的票不合并（老票仍是 voter 哈希）。
- 公开读（`/api/fixes` 等）**不输出 uid**，只在管理读（管理令牌或 reviewer／editor／admin 的 cookie）里带 `member`，需要时再决定是否公开昵称。

### 4. 安全
- `session` cookie 是 HttpOnly、Secure、SameSite=Lax；提交都是 JSON POST，沿用现有的 Origin 白名单（CORS）。不新增接受 GET 改数据的入口，CSRF 面不变。
- 前端不接触 uid；`/api/auth/me` 返回 uid 只为了界面展示（如「我的提交」），不作为提交凭据。
- 被移除（墓碑）的成员、tokenVersion 不符的 cookie 一律当匿名。

### 5. 后面能做的（本方案不含）
- 「我的提交」页：按 uid 列出自己的票、改字、反馈。
- 审阅准确率：用 `member` 与最终裁决对比，给 `review.approve` 等权限（会员 caps 的 `review-score` 来源）。
- 按会员限速、按 caps 限制高清书影。

## 改动范围与风险
- 边缘函数：`feedback.js`（新增 `memberFromRequest`、feedback 记录加 member）、`cellreview.js`、`charfix.js`、`thread.js`（voter 规则）、`members` 相关（uid 生成与补发）、`auth/me.js`（返回 uid）。
- 数据：旧票不动；新票 key 末段对登录会员变成 `m:<uid>`，下游导入脚本（每日导入精校票、`web_opinions.py` 等）要确认能识别这种 voter（目前按十六进制哈希假定长度 16）。**这是要先和整理侧（CV0）对一下的一处**。
- 边缘函数一次请求外部 fetch 约 64 次的上限：多一次读成员记录（已在 `checkMemberCookie` 里），可接受。

## 需要用户定的

2. 公开数据里要不要显示会员（昵称或匿名编号）？默认不显示。
3. 反馈表单里，登录后是否自动带上会员邮箱做联系方式（站方可见）？
