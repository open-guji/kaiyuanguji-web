序

中国现存古籍约二十万种

过去二十年，大量善本已被扫描成影像，放上各馆的检索系统。这是了不起的成就——但事情停在了这里。

影像不是文字，文字不是知识。

今天，一个历史研究者想查阅明朝内阁档案，只能自己逐行阅读手写的原件，无法进行文字搜索；一个红楼梦爱好者想了解一段情节在不同版本的异同，却找不到准确的文本；一个开发者想训练一个真正读得懂文言的模型，找不到干净、可溯源、带版本信息的语料。

问题不在于资料太少，而在于资料没有数字化，也没有结构化。

开源古籍项目要做的，是用学术研究的标准，搭建一套完整的古籍数字化方案：

  • 汇集历代研究成果，做一个准确完整的在线古籍目录，收录所有古籍的元数据；
  • 索引网上所有图书馆与民间整理的影印图像和文字资源；
  • 在前人工作的基础上自研 OCR 引擎，持续进行古籍文本化，并人工校对；
  • 开发一系列工具，包括排版、字体编码与生成、词典等等。

这些是古人的智慧，不是我们的资产。任何人都可以拿去用、改、接到自己的系统里。接下来需要的，是更多人一起，把这条流水线铺满那二十万种古籍。

一

项目计划

整个项目分为三个板块：索引（这书是什么、有哪些版本、在哪里）、文本化（把影像变成可靠文字）、排版与工具（把文字变回一部像样的书）。

板块一 · 古籍索引

一部书是什么，有哪些版本，在哪里能看到

这是整条流水线的骨架——让所有资源有共同的坐标。

历代目录学积累了两千年的成果：《汉书·艺文志》以下的正史志书、四库总目、各家私修书目与考证著作，再加上今天各馆的馆藏目录。它们各自成书、各自成库，彼此不通。我们要做的是把这些成果汇到一处，做成一个准确、完整、可被程序直接使用的在线古籍目录：

  • 一部书是一个可引用的条目，有稳定的标识符；
  • 同一部书的不同版本挂在它下面，注明藏处、丛编、流传；
  • 网上所有可得的影像与文本资源，都挂到对应的条目上，标明来源与可用性；
  • 作者独立成体系，与 CBDB 等外部权威库对接。

数据模型。用四层结构解决「古籍的一本书到底指什么」这个真问题：

作品WORK

抽象的知识内容，不随装订与版次改变。《史记》是一个作品。

版本BOOK

具体装订印刷的物理实体，直接对应扫描件与馆藏。「百衲本《史记》」是一个版本。

丛编COLLECTION

组织容器，可递归嵌套。《四库全书》文渊阁本是一个丛编，其中所收的《史记》是它下辖的一个版本。

实体ENTITY

包括人物、地名、山川等。

四层之间通过 64 位 ID 关联，跨仓库、跨语言一致；文本与元数据分仓存放，靠同一套 ID 互指。

目录整理。从《汉书·艺文志》到《清史稿·艺文志》，加上历代补志与考证著作（姚振宗、王应麟、黄虞稷、钱大昕、焦竑等），以及私修目录。这项工作的难度不在体量，而在判断：同名异书要拆，异名同书要并，撰人有别称要归，断代有分歧要考。我们为此建立了一整套判准与覆核制度——每一条合并都有依据，可以被追问、被推翻。

板块二 · 文本化

把影像变成可靠的文字

各馆已公开的古籍影像以数十万册计。但从影像到可靠文本的这一步，需要技术与人工的高效结合。

古籍 OCR 面对的是繁体、异体字、手写刻本、双行夹注、无标点、版框栏线干扰——通用 OCR 模型在这类材料上的准确率不足以直接使用；专业整理则依赖出版社的人海战术：一部中等篇幅的书，数月工期，成本以十万计。

我们计划结合现有开源技术，在自研工具与资深校对人员的深入配合之下，持续推动古籍的文本化。不同于现在网络上流传的良莠不齐的古籍文本，我们将坚持以学术出版级的准确度为目标进行整理，尽量保留生僻字、异体字，甚至 Unicode 未收字。整理平台也将在后期开源，鼓励更多人持续贡献。

01
自研识别管线

open-guji-cv 从图像预处理、版面切分一路做到单字识别与上下文裁决，每一步都有独立的数据集与评测脚本。

02
多源交叉校对

把识别结果与网上公开的文本逐一比对，差异处即为潜在错误。人工校对由此从「全量通读」降到「只看差异」。

03
文本全网首发

一批重要古籍至今在网上找不到任何可用文本，我们正在为它们做文字化，包括《永乐大典》《崇祯历书》《崇祯长编》《明代武职选簿》等。

还差什么

  • 识别精度离脱离人工还差得远。我们希望最终超越现有方案（如 PaddleOCR、识典古籍），在第一轮机器识别中达到 99% 甚至更高的准确率，并全面支持 Unicode 字符集。
  • 协作校对平台尚未上线。一校／二校／终审的流程、字典工具的配套还在开发中。

板块三 · 排版与工具

把文字变回一部像样的书

现有的数字文本普遍丢掉了版式信息：夹注（双行小字注）被压平成正文，注与经混为一谈；眉批、侧批直接消失；异体字被粗暴归并到通用字，字形差异这一版本鉴定的关键线索随之消失。

这类损失是不可逆的。一部书被草率地「数字化过一遍」，往往等于被「永久损失一遍」——因为下一个人会认为这本已经做过了，不必再做。

所以我们把版式当成一等公民，而不是「文字整理完再考虑怎么排」。围绕这一点，再补上字体编码与生成、校勘比对、词典等一系列工具。

01
排版引擎

luatex-cn 基于 LuaTeX，实现古籍版式的像素级复刻——版心、夹注、侧批、眉批、脚注、印章、句读、乌丝栏、改字、抬头——已在四库全书文渊阁本、红楼梦甲戌本等底本上做到版面级还原，可快速生成 PDF。项目已开源发布至 GitHub 并被 CTAN 收录，任何人都能直接安装使用。

02
字体与补字

open-guji-fonts 收录古籍整理中遇到的 Unicode 未收字形，并在此基础上开发一套收字尽可能全的开源字体。

还差什么

  • luatex-cn 对特殊版式的支持尚不完善，如表格、族谱等。
  • 异体字体系仍在建设。目标是在网页与 PDF 中都能便捷地支持 Unicode 未收字，并加快字体设计的速度。
  • 网页端的竖排阅读。已有浏览器渲染的基础实现，但离目标还远——希望做到图文对读、横竖排与繁简体一键切换。
二

可持续性与开放承诺

开源古籍是纯公益的开源基础设施。我们不做数据私有化，不设注册墙，不把公有领域的内容再度圈起来。

我们的开放承诺

  • 核心数据与工具永久开源，采用 CC0 / Apache 2.0 开放许可；
  • 提供批量下载与 API，不设注册墙，在带宽允许的情况下免费提供所有资源；
  • 不将公有领域内容再度私有化；
  • 所有整理成果标注来源与依据，可被追问、可被推翻；
  • 项目进展、设计文档、已知问题全部公开。

我们的版权承诺

古籍的文字与图片在任何国家都属于公有版权。我们承诺所有的数字化工作都从古籍本身出发，合理使用开源工具与公开资源进行整理，并充分尊重现代出版社和作者的点校、注释、翻译等创作产生的著作权。

三条支撑路径

社区协作ONE

参照维基文库的模式，把整理任务拆分到志愿者可以承担的粒度：校一页、补一条、录一部。配合 Git 的版本控制与一校／二校／终审流程，让贡献可追溯、可回滚、可致谢。

公益资助TWO

我们欢迎面向文化遗产数字化、开源基础设施、数字人文的资助计划与专项基金。我们承诺成果完全公开，进展与资金使用完全可查。

机构共建THREE

图书馆、高校、研究机构提供资料、专业判断与人力；我们提供标识体系、工具链与技术支持。成果双方共有，并且必须开放。这是我们对合作的唯一硬条件。

我们做四件别人没在做的事：

标识层IDENTIFIER

给作品、版本、丛编、人物一套开放的、可跨库引用的 ID。

结构层STRUCTURE

把著录、提要、版本关系、存佚状况变成结构化数据，而不是一段说明文字。

工具层TOOLING

把从影像到成品的每一环都做成可独立使用的开源工具。

文本层TEXT

开源分享所有文本并保留排版，最终愿景是对所有传世古籍做精确文本化。

远景
从数字化走向智能化

让古籍不只是被读到，而是变成数字时代的知识。

  • 所有传世古籍做到精确数字化
  • 古籍知识图谱：人物、地点、时间、事件、典籍之间的关联网络；师承交游、引用注疏、时空轨迹
  • 古汉语专用模型的高质量语料与公开评测基线
  • 语义检索、典故溯源、智能注疏

我们清楚这是长期的科学与工程挑战，把它诚实地放在最后，而不是拿来做宣传词。

五

加入我们

古籍浩如烟海，我们只是发起者。期待所有人的参与——你的贡献会随中华文明一同流传下去。

01
写代码

我们缺人的地方很具体：

  • 图像与 OCR——版面识别准确率、字符切分、刻本与手写本的模型微调
  • 前端与网站——索引浏览体验、搜索、竖排阅读器、协作校对界面
  • 排版引擎——表格支持、更多版式特性、issue 处理
  • 数据工程——下载适配器、数据校验、API 与数据分发
02
整理古籍（不需要编程）

需求量最大、也最需要专业判断的部分：

  • 校对已数字化的文本
  • 补充作品提要与描述
  • 录入尚未收录的目录与志书
  • 考订版本、断代、撰人
03
贡献资源与线索

告诉我们哪里还有未被收录的数字资源；指出索引里的错误——网站上有反馈通道，每一条都会被处理；报告新的可用站点。

04
机构合作

图书馆、高校、研究机构、出版社：我们提供标识体系、工具链与技术支持，你提供资料、专业判断与场景。成果双方共有并开放。欢迎直接联系。

05
传播与资助

转发这份文档、在你的论文或项目里引用我们的数据、提供资助。所有资源都会被用在整理工时上，投入与产出全部公开可查。
